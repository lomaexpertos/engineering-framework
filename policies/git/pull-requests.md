# Pull requests

## Requirements

1. Un Pull Request **MUST** identificar objetivo, alcance, riesgos materiales y
   validaciones ejecutadas con suficiente contexto para revisarlo.
2. La rama base y el diff efectivo **MUST** verificarse antes de aprobar o solicitar
   merge.
3. Checks, branch protection y revisiones requeridas **MUST NOT** eludirse para
   integrar un cambio.
4. Un cambio incompatible, destructivo o de alto impacto **MUST** hacer visibles su
   rollout, recuperación y coordinación necesaria.
5. Aprobar, solicitar cambios, habilitar auto-merge o cerrar un Pull Request **MUST**
   requerir autoridad explícita sobre esa acción externa.
